What Is Spry?

Slide 5 of 30 #

What Is the Spry Framework?

Adobe JavaScript widget library bundled with Dreamweaver CS3–CS6 (2007–2012).

Provided dropdown menus, accordions, tabbed panels without writing JS manually.

Required three files per widget: specific HTML + CSS file + JS file + init script.

×
Do NOT use Spry in new projects. It is unmaintained, insecure, and not mobile-friendly.
6

The Three Spry Widgets

Slide 6 of 30 #

Spry Widget Types

Accordion

Stacked collapsible panels. Only one open at a time.

Used for FAQs, event details.

Tabbed Panels

Content organized under clickable tabs, like browser tabs.

Used for workshops/social/events sections.

Menu Bar

Horizontal or vertical navigation with dropdown submenus.

Most relevant to our Student Club site.

Each widget required: (1) specific HTML classes, (2) linked CSS file, (3) linked JS file, (4) initialization script. Missing any one breaks it.

Recognizing Spry Code

Slide 7 of 30 #

What Spry Code Looks Like

html
1<!-- Spry Accordion (LEGACY) -->2<div id="Accordion1" class="Accordion">3  <div class="AccordionPanel">4    <div class="AccordionPanelTab">Title</div>5    <div class="AccordionPanelContent">6      <p>Content here</p>7    </div>8  </div>9</div>10<!-- Required files in <head>: -->11<link href="SpryAssets/SpryAccordion.css"12  rel="stylesheet">13<script src="SpryAssets/SpryAccordion.js"></script>14<!-- Init script at bottom of page: -->15<script>var Accordion1 =16  new Spry.Widget.Accordion("Accordion1");17</script>

If you see class names starting with "Spry", "Accordion", "MenuBar", or "TabbedPanels" — it's Spry.

Three dependencies: HTML classes + CSS file + JS file + init script. Remove any one and the widget breaks silently.

8

Why Spry Is Legacy

Slide 8 of 30 #

Five Reasons Spry Is Obsolete

1. No longer maintained since ~2012 — no patches, no fixes

2. Not mobile-friendly — touch events not handled; dropdowns fail on phones

3. Security risks — unmaintained JS may contain unpatched vulnerabilities

4. Better alternatives exist — modern CSS replicates all widgets without JS

5. Browser compatibility — outdated JS patterns break in Chrome 100+, Safari 16+

9

Spry vs Modern Alternatives

Slide 9 of 30 #

Comparison Table

Accordion

Spry: JS + CSS + init → Modern: <details> + <summary> (pure HTML5)

Tabbed Panels

Spry: JS + CSS + init → Modern: radio-button hack or details name=

Menu Bar

Spry: JS + CSS + init → Modern: nested ul + :hover/:focus-within

File count

Spry: 4+ files per widget → Modern: 0 extra files

Maintenance

Spry: dead since 2012 → Modern: part of HTML/CSS standard forever

Mobile

Spry: broken on touch → Modern: works natively on all devices

i
Key insight: if behavior can be triggered by hover, focus, or click on summary, CSS can respond without JavaScript.

Try It Now: CSS-Only Mobile Menu

Slide 12 of 30 #

Five minutes — a toggle menu with zero JavaScript

HTML

html
1<input type="checkbox" id="menu-toggle"2       class="menu-checkbox">3<label for="menu-toggle"4       class="menu-button">&#9776; Menu</label>56<nav class="mobile-nav">7  <ul>8    <li><a href="index.html">Home</a></li>9    <li><a href="about.html">About</a></li>10  </ul>11</nav>

CSS

css
1.menu-checkbox { display: none; }2.mobile-nav { display: none; }34.menu-checkbox:checked ~ .mobile-nav {5  display: block;6}

What to check

1. The checkbox itself is hidden — you only see the label.

2. Click the label — clicking a <label for="x"> toggles checkbox #x.

3. The nav appears. Click again and it hides.

4. The ~ is the general sibling selector: nav must come AFTER the checkbox.

i
This is the checkbox hack. It works because :checked is a real CSS state, so no JavaScript is needed.

CSS Positioning Refresher

Slide 13 of 30 #

Positioning Refresher

position: relative

The element stays in normal flow but becomes a reference point for any absolutely positioned children.

Without it, absolute children measure from the nearest ancestor that has a position set — often the page itself.

position: absolute

The element is removed from normal flow and positioned relative to its nearest positioned ancestor.

top: 100% means "place my top edge at the bottom edge of my parent."

In dropdowns: The parent li gets position: relative. The nested ul.dropdown gets position: absolute + top: 100%. This pins the panel directly below the parent menu item.

i
If you forget position: relative on the li, the dropdown measures from the page corner instead. This is the most common positioning bug in CSS navigation.

Worked Example: CSS Dropdown Nav

Slide 14 of 30 #

Complete CSS-Only Dropdown Navigation

html
1<!-- HTML: nested ul inside li -->2<nav>3  <ul class="main-nav">4    <li><a href="index.html">Home</a></li>5    <li class="has-dropdown">6      <a href="events.html">Events ▾</a>7      <ul class="dropdown">8        <li><a href="workshops.html">9          Workshops</a></li>10        <li><a href="films.html">11          Film Nights</a></li>12        <li><a href="talks.html">13          Career Talks</a></li>14      </ul>15    </li>16    <li><a href="join.html">Join</a></li>17    <li><a href="contact.html">Contact</a></li>18  </ul>19</nav>
css
1.main-nav { list-style: none;2  display: flex; gap: 0; padding: 0; }3.main-nav > li { position: relative; }4.main-nav a { display: block;5  padding: 10px 18px; color: #fff; }67/* hidden by default */8.dropdown { display: none;9  position: absolute; top: 100%;10  left: 0; min-width: 180px;11  background: #1a1a2e; z-index: 1000;12  list-style: none; padding: 0; }1314/* show on hover OR keyboard focus */15.has-dropdown:hover .dropdown,16.has-dropdown:focus-within .dropdown {17  display: block; }

position: relative on the parent li makes it the origin point for the absolutely positioned dropdown panel.

top: 100% places the panel exactly at the bottom edge of the parent li.

:focus-within ensures keyboard users can Tab into the submenu. Without it, only mouse hover works.

z-index: 1000 keeps the dropdown above other page content.

i
Result in browser: hovering or tabbing to "Events" reveals three sub-links. No JavaScript needed.

Try It Now: Build a Dropdown

Slide 15 of 30 #

Five minutes — add a dropdown to your nav

Add this to your HTML

html
1<nav>2  <ul>3    <li><a href="index.html">Home</a></li>4    <li>5      <a href="#">Activities ▾</a>6      <ul>7        <li><a href="#">Sports</a></li>8        <li><a href="#">Music</a></li>9        <li><a href="#">Art</a></li>10      </ul>11    </li>12    <li><a href="about.html">About</a></li>13  </ul>14</nav>

Then add this CSS

css
1nav ul li { position: relative; }2nav ul li ul {3  display: none;4  position: absolute;5  top: 100%;6  left: 0;7  z-index: 10;8}9nav ul li:hover > ul,10nav ul li:focus-within > ul {11  display: block;12}
i
Hover over "Activities" — the submenu should appear below it. If it appears in the wrong place, check position: relative on the li.

Worked Example: CSS Accordion

Slide 16 of 30 #

Complete CSS-Only Accordion

html
1<div class="css-accordion">2  <details open>3    <summary>Web Design Workshop</summary>4    <div class="accordion-content">5      <p>Learn HTML & CSS basics.</p>6      <p><strong>Date:</strong> March 15</p>7      <p><strong>Room:</strong> Lab A</p>8    </div>9  </details>1011  <details>12    <summary>Photo Walk</summary>13    <div class="accordion-content">14      <p>Explore campus with cameras.</p>15      <p><strong>Meet:</strong> Main Gate, 9 AM</p>16    </div>17  </details>1819  <details>20    <summary>Hackathon 2024</summary>21    <div class="accordion-content">22      <p>48-hour coding challenge!</p>23      <p><strong>Teams:</strong> 2–4 students</p>24    </div>25  </details>26</div>

<details open>: first panel starts open so visitors see content immediately.

<summary>: the always-visible clickable header. Browser adds a triangle automatically.

Everything after summary is the collapsible body. Hidden until clicked.

Multiple <details> siblings: each operates independently. Add name="group" to make them exclusive (one open at a time).

Zero JavaScript: the browser handles all open/close logic natively.

Accessibility: screen readers announce the summary text and the expanded/collapsed state.

i
Compare to Spry: same visual result, but 0 KB of JavaScript, full mobile support, and semantic HTML.

Sub-Submenus & Advanced Patterns

Slide 17 of 30 #

Going Deeper: Multi-Level Dropdowns

html
1<li class="has-dropdown">2  <a href="events.html">Events ▾</a>3  <ul class="dropdown">4    <li class="has-dropdown">5      <a href="#">Workshops ▸</a>6      <ul class="dropdown">7        <li><a href="web.html">Web</a></li>8        <li><a href="photo.html">Photo</a></li>9      </ul>10    </li>11    <li><a href="films.html">Films</a></li>12  </ul>13</li>

Same pattern, nested: Each sub-level is another li.has-dropdown with its own ul.dropdown inside.

CSS stays identical: The same .dropdown rules apply at every nesting level because they target any .dropdown descendant of .has-dropdown.

left: 100% on nested dropdowns opens them to the right instead of below. Use this for sub-submenus.

z-index stacking: Each deeper level needs a higher z-index so it appears above its parent panel.

!
Limit nesting to 2–3 levels. Deeper menus are hard to navigate on mobile and confuse users.

Dropdown Accessibility

Slide 19 of 30 #

Hover-Only Menus Exclude People

The problem

:hover requires a mouse. Keyboard users and touch-screen users never trigger it.

A submenu that only opens on hover is invisible to anyone tabbing through the page.

The fix

css
1.dropdown:hover .submenu,2.dropdown:focus-within .submenu {3  display: block;4}

:focus-within keeps the submenu open while any child link has keyboard focus.

aria-haspopup

Add aria-haspopup="true" to the parent link.

Tab test

Tab through the nav with no mouse. Every submenu link must be reachable.

Touch

On phones, prefer a click/checkbox toggle over hover entirely.

!
Always pair :hover with :focus-within. One line of CSS makes the menu usable for keyboard users.

Common Mistakes

Slide 22 of 30 #

7 Common Mistakes (and Fixes)

1. Using Spry in a new project — it is dead; use CSS-only solutions

2. Forgetting position: relative on parent li — dropdown flies to page corner

3. Using :hover without :focus-within — locks out keyboard/touch users

4. Forgetting z-index on dropdown — hides behind other content

5. Using div instead of details for accordions — loses semantics and accessibility

6. Putting summary anywhere except first child of details — browser renders blank toggle

7. Patching old Spry code instead of replacing it — waste of time; rebuild native

Debug This

Slide 23 of 30 #

This dropdown does not work. Why?

Buggy CSS

css
1nav ul li {2  display: inline-block;3}45nav ul li ul {6  display: none;7  position: absolute;8}910nav ul li:hover > ul {11  display: block;12}

Bugs

1. No position: relative on nav ul li — the absolute dropdown positions itself relative to the viewport, not the parent.

2. No z-index on the dropdown — it hides behind page content.

3. No :focus-within — keyboard users cannot open the dropdown.

4. No min-width on dropdown — it collapses to the width of the text.

i
Fix: add position: relative to li, z-index: 10 to dropdown, :focus-within alongside :hover, and min-width: 200px.

Do vs Don't

Slide 24 of 30 #

Do vs Don't

Do

Use <details> + <summary> for accordions

Include :focus-within with :hover on dropdowns

Set position: relative on the parent li

Add z-index to keep dropdowns above content

Replace Spry widgets when you inherit a legacy site

Test keyboard navigation (Tab through every menu)

Don't

Start new projects with Spry framework

Use :hover alone without :focus-within

Put summary anywhere except first child of details

Patch old Spry JS instead of replacing it

Nest dropdowns deeper than 3 levels

Forget to delete the SpryAssets folder after migration

Try It Now: Native Accordion

Slide 25 of 30 #

Three minutes — an accordion with no CSS tricks at all

HTML only

html
1<details>2  <summary>When do we meet?</summary>3  <p>Every Tuesday at 6pm in Room B203.</p>4</details>56<details open>7  <summary>How do I join?</summary>8  <p>Fill in the form on the Contact page.</p>9</details>

Optional styling

css
1details {2  border: 1px solid #ddd;3  border-radius: 6px;4  padding: 12px;5  margin-bottom: 8px;6}7summary { cursor: pointer; font-weight: 700; }

What to check

1. Click a summary — the panel opens and closes.

2. The second one starts open because of the open attribute.

3. Tab to a summary and press Enter — it works with the keyboard for free.

4. Zero JavaScript, zero CSS required for the behaviour.

✓
This is what Spry accordions needed 200 lines of JavaScript to do. Two HTML tags replaced all of it.
