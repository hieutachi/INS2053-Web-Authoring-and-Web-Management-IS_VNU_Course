What Is a 'Site'?

Slide 5 of 34 #

Defining your site

A site = the root folder containing ALL files for one website. Tell your editor where it lives.

Dreamweaver

Site → New Site → set name + local folder

Files panel shows project tree

VS Code

File → Open Folder → select root

Explorer panel shows project tree

!
Analogy: Setting up an apartment — choose rooms (subfolders), move furniture in (files), give your address to the landlord (define the site).

Your Site Is Just a Folder

Slide 6 of 34 #

Your site is just a folder

Photo: allispossible.org.uk — CC BY 2.0, Wikimedia Commons

A Dreamweaver "site" is NOT something uploaded to the internet.

It is one folder on YOUR computer — called the local root folder.

The manila folder in the photo = your local root folder.

Documents inside = your .html, .css, and image files.

Site > New Site simply tells Dreamweaver which folder to watch.

i
For CodeBreakers club: your folder might be C:\sites\codebreakers\ — that entire folder IS your site.
Speaker notes
Self-study note: Many students think a Dreamweaver 'site' is something online. Emphasize that it is just one folder on their own computer. The manila folder in the photo is a perfect analogy — your local root folder holds all documents, just like a physical folder holds papers. Site Setup only tells Dreamweaver which folder to watch; nothing is uploaded anywhere yet.

Folder Organization Rules

Slide 8 of 34 #

Six rules for clean folders

One root folder per project — keeps everything contained and portable.

Separate by file type — images/, css/, js/, documents/.

HTML pages in root only — everything else goes in subfolders.

Two levels maximum — root → subfolder → files. No deep nesting.

Lowercase folder names — avoids case-sensitivity issues on Linux servers.

No spaces in folder names — spaces become %20 in URLs.

i
If you need a new folder mid-project, create it immediately. Never dump files in the wrong place.

Relative vs Absolute Paths

Slide 10 of 34 #

File paths: relative vs absolute

Relative (ALWAYS use)
html
1<img src="images/logo.png">2<a href="about.html">About</a>
Absolute (NEVER use)
html
1<img src="C:\Users\...\logo.png">2<a href="C:\...\about.html">

Relative paths work after moving folders, sharing projects, or uploading to a server. Absolute paths break.

The ../ Rule

Slide 12 of 34 #

The ../ rule — going up a folder

When linking FROM a subfolder, use ../ to go up one level first.

css
1/* Inside css/style.css */2header {3    /* Go UP one level, then into images/ */4    background-image: url("../images/banner.jpg");5}
13

Common Path Scenarios

Slide 13 of 34 #

From where to where?

From index.html to about.html → about.html (same folder)

From index.html to images/logo.png → images/logo.png (into subfolder)

From css/style.css to index.html → ../index.html (up one level)

From css/style.css to images/logo.png → ../images/logo.png (up, then down)

From pages/events.html to index.html → ../index.html (up one level)

!
If an image does not display, the FIRST thing to check is whether the relative path is correct.

Try It Now: Fix These Paths

Slide 15 of 34 #

Five minutes — fix four broken paths

You are editing pages/about.html. Fix these hrefs:

html
1<!-- Bug 1: link to home page -->2<a href="index.html">Home</a>34<!-- Bug 2: link to contact page -->5<a href="contact.html">Contact</a>67<!-- Bug 3: link to stylesheet -->8<link rel="stylesheet" href="style.css">910<!-- Bug 4: link to image -->11<img src="images/logo.png" alt="Logo">

What to check

about.html is inside pages/. To reach index.html, you need to go UP one folder.

contact.html is in the same folder — no ../ needed.

style.css is in css/, which is at the root — need ../css/style.css.

images/ is at the root — need ../images/logo.png.

i
Open each fixed link in the browser. If you see a 404, the path is still wrong.

Git Vocabulary

Slide 20 of 34 #

Key terms explained

Repository (repo) — A project tracked by Git. Like a photo album.

Commit — A saved snapshot. Like a photo in the album.

Stage — Changes ready to be committed. Photos laid out before adding to album.

Push — Upload commits to GitHub. Sending photos to cloud storage.

Pull — Download commits from GitHub. Getting photos from cloud.

Clone — Download an entire repo. Copying someone's photo album.

i
Git is optional for this course but HIGHLY recommended. Commit early and often!

Worked Example 1: Paths from Root

Slide 22 of 34 #

Linking images and CSS from index.html

html
1<!-- Inside index.html (root folder) -->2<head>3  <link rel="stylesheet"4        href="css/style.css">5</head>6<body>7  <img src="images/event-workshop.jpg"8       alt="Web Design Workshop"9       width="400" height="300">10</body>

href="css/style.css" — index.html is in root, css/ is a subfolder. Just go INTO css/.

src="images/event-workshop.jpg" — same logic: root → images/ subfolder.

No ../ needed because we are starting from the root folder.

i
Rule: When the source file is in the root, paths to subfolders never start with ../

Worked Example 2: Multi-Page Links

Slide 23 of 34 #

Two pages linked together

html
1<!-- index.html -->2<nav>3  <ul>4    <li><a href="index.html"5           class="active">Home</a></li>6    <li><a href="about.html">About</a></li>7    <li><a href="contact.html">Contact</a></li>8  </ul>9</nav>1011<!-- about.html (same nav!) -->12<nav>13  <ul>14    <li><a href="index.html">Home</a></li>15    <li><a href="about.html"16           class="active">About</a></li>17    <li><a href="contact.html">Contact</a></li>18  </ul>19</nav>

Same nav block — copy-paste the exact same <nav> into every page so users never get lost.

class="active" — move this to the current page's link so visitors know where they are.

href="about.html" — relative path: both files are in the root folder, so just use the filename.

<title> — different on each page for SEO and usability.

i
Test every link on every page! Click Home, About, Contact from each page. Fix any broken links before moving on.

From a subfolder like css/, use ../index.html to go up first.

Discussion: Why Same Nav Everywhere?

Slide 24 of 34 #

Why must every page have the same navigation?

Imagine a store where the exit sign moves to a different wall on every floor.

Users expect consistent navigation. If links change, they get lost and leave.

Copy-paste the <nav> block into every page. Later we will learn techniques to avoid repetition.

i
For now, manual copying is perfectly fine. Focus on getting it right.

Common Mistakes

Slide 25 of 34 #

Watch out for these mistakes

×
Using absolute paths (C:\...) in HTML — breaks when you move the folder
×
Forgetting ../ when linking from a subfolder — browser looks in wrong place
×
Inconsistent file names (About.html vs about.html) — Linux servers are case-sensitive

Debug This

Slide 29 of 34 #

Every link below is broken. Why?

html
1<!-- File: pages/about.html -->2<a href="/index.html">Home</a>3<a href="pages/contact.html">Contact</a>4<img src="C:\Users\Nam\site\images\logo.png" alt="Logo">5<link rel="stylesheet" href="style.css">
Link 1

/index.html means the server root. Opened locally that resolves to your C: drive. Use ../index.html

Link 2

We are already inside pages/, so pages/contact.html looks for pages/pages/. Use contact.html

Image

An absolute Windows path only works on your machine. Use ../images/logo.png

CSS

style.css is not in pages/. Use ../css/style.css

i
Rule of thumb: count how many folders up you must climb, then write that many ../ before the path.

Accessibility: Structure That Helps Everyone

Slide 30 of 34 #

Folder and Naming Choices Are Accessibility Choices

Names

about-us.html reads clearly in a screen reader's URL announcement; page2.html tells the user nothing.

Case

Use lowercase everywhere. Linux servers are case-sensitive, so About.html works locally and 404s live.

Spaces

Spaces become %20 in URLs — ugly and error-prone. Use hyphens: student-club.html

Nav order

Keep nav links in the same order on every page. Users navigating by keyboard memorise the tab count.

index.html

Servers serve index.html automatically, so the user can type just the folder name. Any other name forces the full path.

!
A broken link is the most common accessibility failure in student projects, and the easiest to prevent.
