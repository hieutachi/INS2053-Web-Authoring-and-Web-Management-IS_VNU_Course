Media Query Breakpoints

Slide 7 of 30 #

Mobile first, and one query taken apart

8

Common Breakpoints

Slide 8 of 30 #

Breakpoint Quick Reference

480px

Small phones — tighter spacing, smaller headings

768px

Tablets / large phones — stack columns, compact nav

1024px

Landscape tablets — may restore some side-by-side layout

1200px

Desktops — full layout, max-width container

min-width (mobile-first): base rules are the phone layout; queries ADD complexity as screen grows. Ascending order: 480px, then 768px.

max-width (desktop-first): base rules are the desktop layout; queries OVERRIDE for smaller screens. Exercises use this approach.

i
Pick one direction per project. Do not mix min-width and max-width unless you have a specific reason.

Try It Now: Add a Media Query

Slide 9 of 30 #

Five minutes — make your page responsive

Add this to the bottom of style.css

css
1/* Mobile: screens 768px and below */2@media (max-width: 768px) {3  body {4    font-size: 14px;5  }67  nav ul {8    flex-direction: column;9  }1011  .two-column {12    flex-direction: column;13  }1415  img {16    max-width: 100%;17    height: auto;18  }19}

Then test it

1. Press F12 → click the device toolbar icon (or Ctrl+Shift+M).

2. Select "iPhone SE" or set width to 375px.

3. The nav links should stack vertically, not overflow.

4. The two-column layout should become one column.

i
If nothing changes, check that the media query is at the BOTTOM of the CSS file (later rules override earlier ones).

Try It Now: Auto-Responsive Grid

Slide 10 of 30 #

Four minutes — a grid that reflows with no media query

HTML

html
1<div class="card-grid">2  <article class="card">Card 1</article>3  <article class="card">Card 2</article>4  <article class="card">Card 3</article>5  <article class="card">Card 4</article>6</div>

CSS

css
1.card-grid {2  display: grid;3  grid-template-columns:4    repeat(auto-fit, minmax(250px, 1fr));5  gap: 20px;6}78.card {9  border: 1px solid #ddd;10  border-radius: 8px;11  padding: 16px;12}

What to check

1. On a wide window you get 3–4 columns.

2. Narrow the window slowly — columns drop to 2, then 1.

3. You wrote zero media queries. auto-fit did the work.

4. minmax(250px, 1fr): never narrower than 250px, otherwise share space equally.

i
auto-fit + minmax is the single most useful responsive pattern in modern CSS. Memorise this line.

Flexible Images & Touch Targets

Slide 11 of 30 #

Two Rules You Must Always Apply

Flexible Images

css
1img {2  max-width: 100%;3  height: auto;4}

Image shrinks to fit its container but never grows beyond natural size. height: auto preserves aspect ratio.

Touch Targets (44px minimum)

css
1nav a, .btn {2  min-height: 44px;3  padding: 12px 16px;4}

Average fingertip contact area is ~44x44 CSS pixels. Buttons and links below this cause mis-taps. Apple HIG + WCAG 2.5.5 standard.

!
font-size: 16px on form inputs prevents iOS Safari from auto-zooming on focus.

Worked Example: Mobile-First CSS

Slide 12 of 30 #

Complete Mobile-First Responsive Layout

css
1/* === BASE: phone (375px) === */2.container { padding: 12px; }3.nav { display: flex; flex-direction: column; }4.nav a { padding: 12px; /* 44px touch target */ }5.cards { display: grid;6  grid-template-columns: 1fr; gap: 16px; }7.hero-img { width: 100%; height: auto; }8.sidebar { display: none; }910/* === LARGE PHONE (480px+) === */11@media (min-width: 480px) {12  .hero-title { font-size: 2rem; }13  .cards { gap: 20px; }14}1516/* === TABLET (768px+) === */17@media (min-width: 768px) {18  .container { padding: 24px; max-width: 720px;19    margin: 0 auto; }20  .nav { flex-direction: row; }21  .cards { grid-template-columns: 1fr 1fr; }22  .sidebar { display: block; }23}

Base rules first: these ARE the phone layout. No media query needed for 375px.

flex-direction: column stacks nav links vertically on phones. Each link has 12px padding for 44px touch targets.

grid-template-columns: 1fr means one column on phones. Cards stack naturally.

width: 100%; height: auto makes images shrink to fit any screen without distortion.

@media (min-width: 480px) adjusts font sizes and spacing for larger phones. Ascending order: 480px before 768px.

@media (min-width: 768px) adds two-column cards, horizontal nav, and shows the sidebar. Rules ADD, never undo.

i
Test in Chrome DevTools: press F12, toggle Device Toolbar (Ctrl+Shift+M), resize to 375px / 480px / 768px and watch the layout change.

Worked Example: Desktop-First CSS

Slide 13 of 30 #

Desktop-First Approach (Exercises Use This)

css
1/* === DESKTOP DEFAULTS === */2main { width: 65%; float: left; padding: 25px; }3#sidebar { width: 35%; float: left; }4.gallery-item { width: calc(33.33% - 10px); }56/* === TABLET (<=768px) === */7@media (max-width: 768px) {8  main, #sidebar { width: 100%; float: none; }9  #sidebar { border-top: 2px solid #2874a6;10    margin-top: 20px; }11  .gallery-item { width: 100%; }12  .btn { display: block; width: 100%;13    padding: 14px; font-size: 16px; }14}1516/* === SMALL PHONE (<=480px) === */17@media (max-width: 480px) {18  header h1 { font-size: 24px; }19  nav ul li a { padding: 8px 10px;20    font-size: 12px; }21  main { padding: 10px; }22}

Base rules = desktop: the non-query styles build the full two-column layout.

max-width: 768px overrides for tablets/phones: stacks columns, removes floats, full-width buttons.

max-width: 480px further reduces heading sizes and padding for small phones.

Order matters: 768px query BEFORE 480px query. Both apply at 375px, but 480px rules come later and win for overlapping properties.

float: none undoes the desktop float layout. On mobile, elements stack naturally in document order.

i
Both approaches produce the same visual result. Pick one direction per project and stay consistent.

Testing with Chrome DevTools

Slide 14 of 30 #

How to Test Responsive Design

Step-by-Step

1. Open page in Chrome

2. Press F12 to open DevTools

3. Click Device Toggle icon (or Ctrl+Shift+M)

4. Select a device preset or drag to custom width

5. Rotate between portrait and landscape

What to Check

Navigation usable (stacked or scrollable)?

Text readable without zooming?

Images within screen bounds?

Buttons tappable (44px+ tall)?

Forms fillable (full-width inputs)?

No horizontal scroll bar?

i
Test at minimum three widths: 375px (phone), 768px (tablet), 1200px (desktop). Resize slowly to catch layout breaks.

Try It Now: Stack the Nav on Mobile

Slide 16 of 30 #

Four minutes — horizontal on desktop, vertical on phone

Mobile-first CSS

css
1/* Base = mobile: stacked */2nav ul {3  list-style: none;4  display: flex;5  flex-direction: column;6  gap: 8px;7  padding: 0;8}910nav a {11  display: block;12  padding: 12px;13  min-height: 44px;14}1516/* Tablet and up: horizontal */17@media (min-width: 768px) {18  nav ul {19    flex-direction: row;20    gap: 20px;21  }22}

What to check

1. Open DevTools (F12) and toggle device toolbar (Ctrl+Shift+M).

2. Pick iPhone SE — links stack vertically, each easy to tap.

3. Switch to iPad — links line up horizontally.

4. min-height: 44px is the Apple-recommended minimum touch target.

5. display: block on the link makes the whole padded area tappable.

i
Mobile-first means the base CSS is the phone layout. Media queries only ADD complexity for bigger screens.

Common Mistakes

Slide 18 of 30 #

7 Common Mistakes (and Fixes)

1. Forgetting the viewport meta tag — everything tiny on mobile

2. Fixed-width images — overflow on narrow screens; use max-width: 100%

3. Only testing on desktop — resize to 375px, 768px, 1200px minimum

4. Tiny touch targets — nav links and buttons must be at least 44px tall

5. Disabling zoom (user-scalable=no) — accessibility violation

6. Writing the media query before the base rule — the base wins and the query does nothing

7. Mixing min-width and max-width in the same project — confusing cascade

19

Responsive Do vs Don't

Slide 19 of 30 #

Responsive Design: Do vs Don't

Do

Include the viewport meta tag on every page

Use max-width: 100% on all images

Write base styles first, then add media queries

Make touch targets at least 44px tall

Test at 375px, 768px, and 1200px minimum

Pick one strategy: mobile-first OR desktop-first per project

Don't

Skip the viewport meta tag (everything renders tiny)

Set fixed pixel widths on images or containers

Use user-scalable=no (blocks zoom for low-vision users)

Mix min-width and max-width in the same stylesheet

Only test on your laptop screen

Hide content with display: none just to fit small screens

Debug This

Slide 20 of 30 #

This responsive CSS has three bugs. Find them.

Buggy CSS

css
1/* Desktop styles */2.container {3  width: 960px;4  margin: 0 auto;5}67/* Mobile */8@media (max-width: 768px) {9  .container {10    width: 960px;11  }1213  nav ul li {14    display: inline-block;15  }1617  img {18    width: 960px;19  }20}

Bugs

1. .container width is still 960px inside the media query — should be 100% or auto for mobile.

2. nav ul li is still inline-block — should be display: block to stack vertically on mobile.

3. img width is 960px — should be max-width: 100% to fit the mobile screen.

i
The media query is correct, but the values inside it are still desktop values. The whole point of a media query is to CHANGE the layout.
21

Mobile Accessibility

Slide 21 of 30 #

Small Screens, Bigger Accessibility Stakes

Touch targets

Buttons and links need at least 44×44px of tappable area.

Spacing

Leave 8px minimum between tappable elements so fingers do not hit the wrong one.

Zoom

Never use maximum-scale=1 or user-scalable=no — it blocks users who need to zoom.

Font size

16px minimum for body text. Smaller text triggers auto-zoom on iOS form fields.

Orientation

The layout must work in both portrait and landscape.

No hover

Anything that only appears on :hover is unreachable on touch devices.

!
The viewport meta tag must stay <meta name="viewport" content="width=device-width, initial-scale=1"> — nothing more.

Debug This: Broken Responsive Page

Slide 25 of 30 #

Find five problems

Broken code

html
1<meta name="viewport"2      content="width=1024, user-scalable=no">
css
1.container { width: 1200px; }23img { width: 800px; }45@media (max-width: 768px) {6  .container { width: 1200px; }7}89nav a { padding: 2px; font-size: 11px; }

The five problems

1

viewport says width=1024 — must be width=device-width.

2

user-scalable=no blocks zoom. Remove it — it is an accessibility failure.

3

.container has a fixed 1200px width. Use max-width: 1200px; width: 100%.

4

img width: 800px overflows phones. Use max-width: 100%; height: auto.

5

Nav links are 11px with 2px padding — far below the 44px touch target and 16px text minimum.

!
Bonus: the media query re-declares the same 1200px, so it changes nothing. A media query that repeats the base value is dead code.
