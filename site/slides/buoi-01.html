How the Web Works

Slide 6 of 35 #

How the web works

Your browser asks a server for a page.

The server sends back HTML + CSS files.

The browser renders them into what you see.

Real-life analogy: A website is like a textbook. Each chapter = one .html file. The table of contents = navigation menu. The printing press = web server.

Real Web Servers

Slide 7 of 35 #

What does a real web server look like?

Photo: BalticServers.com — CC BY-SA 3.0, Wikimedia Commons

A web server is just a computer kept on 24/7 so visitors can reach your site any time.

A data center racks hundreds of these servers together with backup power and cooling.

Big sites use many servers; your CodeBreakers club site needs only one cheap plan.

i
While developing, YOUR laptop acts as the server — Live Server or Dreamweaver preview serves files locally.

What Is an HTML File?

Slide 9 of 35 #

HTML = HyperText Markup Language

HTML is NOT a programming language. It describes the STRUCTURE of content using tags.

plain text file, .htmltags describe structureany browser can read it

Like a recipe card: the card = the .html file, the ingredients = your content, the instructions = the tags, and the cook = the browser.

Anatomy of a URL

Slide 10 of 35 #

Breaking down a URL

http://www.codebreakers.club/about.html
PartValueWhat the browser does
Protocolhttp://Tells the browser how to talk to the server (http or https).
Domainwww.codebreakers.clubThe address of the server that holds the site files.
File path/about.htmlWhich specific file on that server to download and display.

If you type just the domain without a path, the server sends back index.html by default.

i
In our course project the URL might be http://localhost:5500/about.html — localhost means your own laptop is the server.
Speaker notes
Walk through each part slowly. Students often confuse the domain with the file path. Remind them that http:// is the protocol, the domain tells the browser WHERE to go, and the path tells it WHICH file to request. In this course all URLs start with http:// or https://.

Two Kinds of Tags

Slide 11 of 35 #

Paired tags vs self-closing tags

Paired (most tags)
html
1<h1>Hello</h1>2<p>A paragraph</p>3<a href="...">Click</a>

Opening tag + content + closing tag

Self-closing (void elements)
html
1<img src="..." alt="...">2<br>3<hr>4<meta charset="UTF-8">

No closing tag needed — they stand alone

×
Tags must nest properly: <p><strong>OK</strong></p> is correct. <p><strong>BAD</p></strong> is broken.

The HTML5 Boilerplate

Slide 17 of 35 #

The HTML5 boilerplate — memorize this!

html
1<!DOCTYPE html>2<html lang="en">3<head>4    <meta charset="UTF-8">5    <meta name="viewport"6          content="width=device-width, initial-scale=1.0">7    <title>Page Title Here</title>8</head>9<body>10    <!-- All visible content goes here -->11</body>12</html>

<!DOCTYPE html> prevents quirks mode. <head> = metadata (invisible). <body> = visible content.

18

Boilerplate Line-by-Line

Slide 18 of 35 #

What each line does

<!DOCTYPE html> — Tells the browser this is HTML5. Without it, browsers enter quirks mode.

<html lang="en"> — Root element. lang="en" declares English for accessibility and SEO.

<meta charset="UTF-8"> — Supports all characters including Vietnamese diacritics.

<meta name="viewport"...> — Makes the page responsive on mobile devices.

<title> — Sets the browser tab text. NOT visible on the page itself.

<body> — Everything visible goes here: headings, paragraphs, images, links.

<!-- comment --> — Invisible notes for developers. Never shown in the browser.

i
Analogy: DOCTYPE = letterhead. head = envelope (metadata). body = the letter content. </html> = signature.

Worked Example 1: Hello World Page

Slide 20 of 35 #

The simplest possible web page

html
1<!DOCTYPE html>2<html lang="en">3<head>4    <meta charset="UTF-8">5    <title>Simple Page</title>6</head>7<body>8    <h1>Hello, World!</h1>9    <p>This is my first web page.</p>10</body>11</html>

<!DOCTYPE html> — Declares HTML5 standards mode.

<title> — Tab reads "Simple Page."

<h1> — Large bold heading on the page.

<p> — Normal paragraph with automatic spacing.

i
In the browser: one large heading and one paragraph below it. The tab says "Simple Page."

Save as index.html → Ctrl+S → F12 to preview.

Worked Example 2: Student Club Home Page

Slide 21 of 35 #

Your first complete web page

html
1<!DOCTYPE html>2<html lang="en">3<head>4    <meta charset="UTF-8">5    <title>Student Club - Home</title>6</head>7<body>8    <h1>Welcome to the Student Club</h1>9    <p>We are a community of students10       who love technology and creativity.</p>1112    <h2>Upcoming Events</h2>13    <ul>14        <li>Web Workshop — Mar 15</li>15        <li>Photo Contest — Mar 22</li>16        <li>Music Night — Mar 29</li>17    </ul>1819    <p>Contact: <a href="mailto:club@university.edu">20       club@university.edu</a></p>21</body>22</html>

<!DOCTYPE html> — tells the browser this is HTML5 (prevents quirks mode).

<title> — text shown in the browser tab only, NOT on the page.

<h1> — largest heading, one per page. Browsers render it bold and large.

<h2> — sub-heading, smaller than h1. Creates section structure.

<ul> + <li> — bulleted list. Each item wrapped in <li> tags.

<a href="mailto:..."> — clickable email link that opens the mail app.

i
In the browser: a large heading, a welcome paragraph, three bullet points, and a clickable email link. The tab reads "Student Club - Home."

Save as index.html → Ctrl+S → F12 to preview.

Discussion: Why Separate Files?

Slide 23 of 35 #

Why not put everything in one file?

A real website has 5, 10, or 50+ pages.

If everything were in one file, it would be enormous and impossible to maintain.

Separate files = easier editing, faster loading, better organization.

i
Think about it: why do textbooks have chapters instead of being one giant wall of text?

We will build multi-page sites starting in Session 2.

Common Mistakes

Slide 24 of 35 #

Watch out for these mistakes

×
Forgetting <!DOCTYPE html> — triggers quirks mode, pages render incorrectly
×
Spaces in filenames — "My Page.html" becomes "My%20Page.html" in URLs
×
Not saving before previewing — browser shows the OLD version
×
Mixing up <head> and <body> — headings go in body, title goes in head
×
No project folder — never save files directly on Desktop
×
Saving as .txt — always verify the extension is .html, not .html.txt
×
Unclosed tags — every <p> needs </p>, every <h1> needs </h1>

Try It Now: Type the Boilerplate

Slide 29 of 35 #

Three minutes — type this from memory

The HTML5 boilerplate

html
1<!DOCTYPE html>2<html lang="en">3<head>4  <meta charset="UTF-8">5  <meta name="viewport" content="width=device-width, initial-scale=1.0">6  <title>My Page</title>7</head>8<body>9  <h1>Hello World</h1>10</body>11</html>

<title> — shows in the browser tab.

i

First HTML File: Do vs Don't

Slide 30 of 35 #

Do vs Don't

Do

Start every page with <!DOCTYPE html>

Set <html lang="en"> and <meta charset="UTF-8">

Name your home page exactly index.html

Use all-lowercase file names with no spaces

Save with the .html extension, not .txt

Don't

Skip the doctype — the browser falls back to quirks mode

Write <Title> or <BODY> in mixed case

Name files "My Home Page.html" with spaces

Nest tags out of order: <b><i>text</b></i>

Forget the closing tag on a container element

Debug This

Slide 31 of 35 #

Three bugs. Find them before you scroll.

html
1<!DOCTYPE html>2<html>3<head>4  <title>My Club<title>5</head>6<body>7  <h1>Welcome</h2>8  <p>Join us today!9</body>10</html>
Bug 1

<title> is never closed — the second one needs a slash: </title>. Everything after it disappears.

Bug 2

<h1> is closed with </h2>. Opening and closing tags must match.

Bug 3

<html> has no lang attribute — add lang="en" so screen readers pick the right voice.

i
The unclosed <p> is legal HTML — the browser closes it at </body> — but closing it yourself is the habit to build.

Accessibility Starts in the Boilerplate

Slide 32 of 35 #

Four Attributes You Set Once Per Page

lang

<html lang="en"> tells a screen reader which language to pronounce. Wrong lang makes speech unintelligible.

charset

<meta charset="UTF-8"> must be first in <head> so accented and Vietnamese characters render instead of showing as ?.

title

<title> is the first thing announced and the label in the browser tab. Never leave it as "Untitled Document".

viewport

The viewport meta tag lets users zoom on a phone. Without it, text is unreadably small.

!
These four lines cost you thirty seconds and decide whether the page is usable at all. Put them in every file from day one.
