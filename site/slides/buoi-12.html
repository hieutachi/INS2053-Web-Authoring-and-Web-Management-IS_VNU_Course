Live Server Setup

Slide 7 of 31 #

Auto-Refresh Preview with Live Server

Setup steps

1. Install "Live Server" by Ritwick Dey

2. Open your project folder (File → Open Folder)

3. Right-click index.html → "Open with Live Server"

4. Browser opens at http://127.0.0.1:5500

Every time you save a file, the browser refreshes automatically.

Why this matters

No more manual save → switch → refresh cycle.

Changes appear instantly as you type.

CSS changes visible without refreshing.

!
Live Server only works when you open a FOLDER, not a single file. File → Open Folder, always.

Emmet Recipes Worth Memorising

Slide 9 of 31 #

Six Abbreviations That Cover Most of a Page

text
1!                     → whole HTML5 boilerplate2nav>ul>li*6>a[href]   → a six-item nav bar3ul>li{Item $}*4       → Item 1 … Item 4
text
1div.card*3>h3+p       → three cards, each h3+p2table>tr*3>td*4       → a 3 by 4 table3d:f / jc:c / mt10     → CSS shorthands
i
$ is a counter and {} is text content, so li{Item $}*4 writes the numbering for you. Both work in .html only — in .css use the property shorthands instead.
Speaker notes
Do not read this list out. Put it on screen, then ask the class to type each one and describe what appeared. The last two rows are the ones that save the most time in the final project: div.card*3>h3+p builds a whole card section, and the CSS shorthands remove most of the typing from a stylesheet.

Try It Now: Emmet Speed Round

Slide 10 of 31 #

Five minutes — type these abbreviations and press Tab

Type these in a .html file

html
1!              → full HTML boilerplate2nav>ul>li*3    → nav with 3 list items3.container     → <div class="container">4#hero          → <div id="hero">5p.text{Hello}  → <p class="text">Hello</p>6ul>li.item$*5  → 5 items with numbered classes

What to notice

! gives you the full HTML5 boilerplate in one keystroke.

> means "child" — nav contains ul contains li.

*3 means "repeat 3 times."

. means class, # means id — just like CSS selectors.

$ is a number counter — item1, item2, item3...

i
If nothing happens when you press Tab, make sure you are in an .html file and Emmet is enabled.

Try It Now: Live Server Workflow

Slide 12 of 31 #

Four minutes — save-and-see instead of save-and-refresh

Steps

1. Right-click index.html in the Explorer panel.

2. Choose "Open with Live Server".

3. The browser opens at http://127.0.0.1:5500.

4. Put VS Code and the browser side by side.

5. Change an <h1> and press Ctrl+S — watch the browser update itself.

What to notice

The address bar shows http://127.0.0.1:5500, not file:///C:/...

Relative paths like images/logo.png now resolve the same way they will on a real server.

You never press F5 again — saving is the refresh.

!
Live Server binds to localhost only, so nobody else on the network can reach it. It is a dev tool, not hosting.

Problems Panel & IntelliSense

Slide 13 of 31 #

Real-Time Error Detection

Problems panel (Ctrl+Shift+M)

Shows errors and warnings in real time.

Red squiggly = error, yellow = warning.

Hover over underlined text to see the message.

Bottom-left corner shows error count: "0 Errors, 0 Warnings" means clean code.

IntelliSense autocomplete

Type <h and wait — VS Code suggests h1-h6, head, header.

Press Tab or Enter to accept a suggestion.

Works for CSS properties too: type mar and get margin, margin-top, etc.

i
Never guess property names or tag names. Let IntelliSense autocomplete them for you — fewer typos.

CSS Validation

Slide 15 of 31 #

Validate CSS Too

How to validate CSS

Go to jigsaw.w3.org/css-validator

Choose "By direct input"

Paste your CSS code and click "Check"

Fix all errors. Target: zero errors.

Common CSS errors

Misspelled property: colr instead of color

Missing semicolon after a value

Invalid value: font-size: big

Unknown property: text-colour

i
CSS validation catches typos that browsers silently ignore. Always validate before submitting.

Worked Example — Debugging with DevTools

Slide 17 of 31 #

Worked Example: Sidebar Below Main Content

Problem: sidebar appears below main, not beside it.

html
1<!-- Inspect in DevTools -->2<div id="main-area">3  <main>...</main>4  <aside id="sidebar"5    style="width:30%; float:left;">6  </aside>7</div>

The Computed panel shows sidebar is 100% wide. Why? Parent has no overflow fix.

Fix (test live in DevTools first):

css
1/* Step 1: Click #main-area in DOM tree */2/* Step 2: Add new property in Styles */3#main-area {4  overflow: hidden;  /* ← type + Enter */5}67/* Sidebar snaps into place instantly! */8/* Step 3: Copy this rule to style.css */9/* Step 4: Save → refresh to confirm */
!
DevTools edits are temporary. Always copy the working value back to your CSS file and save.

Tooling: Do vs Don't

Slide 19 of 31 #

Do vs Don't

Do

Use Live Server so the page reloads as you save

Run W3C validation before submitting anything

Format with Shift+Alt+F to keep indentation consistent

Read the Problems panel — it catches errors before the browser does

Use Emmet abbreviations to type structure faster

Don't

Open HTML with file:// and wonder why paths break

Ignore squiggly underlines in the editor

Mix tabs and spaces in the same file

Install 40 extensions you never use — they slow VS Code down

Edit CSS only in DevTools — those changes vanish on reload

Try It Now: Validate Your Page

Slide 20 of 31 #

Five minutes — find and fix real errors

Steps

1. Open validator.w3.org/nu in a browser.

2. Choose "Check by file upload" and pick your index.html.

3. Click Check. Read every red Error line.

4. Fix the first error in VS Code, save, re-upload, repeat.

5. Then do the same for style.css at jigsaw.w3.org/css-validator.

Errors you will probably see

text
1Error: End tag "div" seen, but there2were open elements.3  -> a nested tag was never closed45Error: An "img" element must have an6"alt" attribute.7  -> add alt="..." to every image89Error: Duplicate ID "header".10  -> IDs must be unique per page
i
Fix errors top to bottom. One unclosed tag often causes five downstream errors that disappear together.

Common Mistakes

Slide 21 of 31 #

Seven Pitfalls to Avoid

1. Coding in Notepad — use VS Code with extensions

2. Ignoring validation errors — validate every page before submitting

3. Manual formatting — set up Prettier + Format on Save (Shift+Alt+F)

4. Edit-save-refresh cycle — use DevTools for live CSS testing

5. Guessing property names — let IntelliSense autocomplete

6. Leaving debug artifacts (console.log, red borders) in submission

7. Opening a single file instead of the folder — Live Server needs a folder

!
Fix: use VS Code with extensions, validate before submit, format on save, test in DevTools first.

Debug This

Slide 22 of 31 #

This page has five bugs. Find them.

Buggy HTML

html
1<!DOCTYPE html>2<html lang="en">3<head>4  <meta charset="UTF-8">5  <title>Club Page</title>6  <link rel="stylesheet" href="style.css">7</head>8<body>9  <h1>Welcome to the Club<h1>10  <p>We meet every <b>Friday</b>.</p>11  <img src="photo.jpg">12  <p>Contact us at club@school.edu13</body>14</html>

Bugs

1. <h1>Welcome to the Club<h1> — missing / in closing tag. Should be </h1>.

2. <img src="photo.jpg"> — missing alt attribute. Add alt="Club photo".

3. <p>Contact us — missing closing </p> tag.

4. <b>Friday</b> — should be <strong> for semantic meaning.

5. No <meta name="viewport"> — page will not be responsive on mobile.

i
Paste this into validator.w3.org to see all five errors listed.

Code Formatting Rules

Slide 25 of 31 #

Clean Code = Professional Code

HTML formatting

2-space indentation (not tabs, not 4 spaces)

Each element on its own line when it has children

Add section comments: <!-- Navigation -->

Self-closing tags (<img>, <br>) on own line

CSS formatting

One property per line

Opening brace on same line as selector

Closing brace on its own line

Blank lines between different selectors

Section comments: /* Header Styles */

i
Use Shift+Alt+F to auto-format. Set up Prettier extension for consistent formatting on every save.

Tools That Audit Accessibility

Slide 29 of 31 #

Let the Machine Find What Your Eyes Miss

Lighthouse

DevTools → Lighthouse → Accessibility. One click gives a score plus a prioritised list of failures with links to fixes.

Contrast

Inspect an element, click the colour swatch: DevTools prints the contrast ratio and flags anything under 4.5:1.

Validator

validator.w3.org catches missing alt attributes, duplicate ids, and mislabelled inputs as HTML errors.

Keyboard

Put the mouse down and press Tab through the page. If you cannot see the focus ring, keyboard users cannot either.

Zoom

Ctrl+Plus to 200%. Text must reflow and stay readable — nothing clipped, nothing overlapping.

!
Automated tools catch roughly a third of real accessibility problems. The Tab-key test finds most of the rest.
