Text Formatting

Slide 8 of 34 #

Paragraphs, bold, italic, breaks

html
1<p>A paragraph of text.</p>23<strong>Important</strong> = bold + semantic4<em>Emphasis</em> = italic + semantic56<br>   = line break (addresses, poetry)7<hr>   = horizontal rule (section divider)
!
Use strong/em instead of b/i for meaningful emphasis.
×
Do NOT use br for spacing — use CSS margin/padding instead.

HTML ignores extra whitespace. Pressing Enter in code does NOT create a new line in the browser.

9

strong/em vs b/i

Slide 9 of 34 #

Same look, different meaning

Semantic (preferred)
html
1<strong>deadline</strong>2<em>strictly</em>

Bold/italic + meaning. Screen readers announce emphasis.

Visual only
html
1<b>product name</b>2<i>foreign word</i>

Bold/italic with NO meaning. Purely visual styling.

i
For beginners: always use <strong> for bold and <em> for italic. These are semantically correct in most situations.

Using br and hr Correctly

Slide 10 of 34 #

When to use br and hr

Correct uses
html
1<!-- br: addresses, poetry -->2<p>Room 101<br>3Building A<br>4University Campus</p>56<!-- hr: thematic section break -->7<hr>
Wrong uses
html
1<!-- WRONG: spacing between sections -->2<p>Section 1</p>3<br><br><br>4<p>Section 2</p>56<!-- Use CSS margin instead! -->
!
br = line break within content (addresses, poems). hr = thematic divider between sections. Neither is for layout spacing.

Lists: ul, ol, Nested

Slide 12 of 34 #

Unordered, ordered, and nested lists

Unordered (bullets)

html
1<ul>2  <li>Web Workshop</li>3  <li>Photo Contest</li>4  <li>Music Night</li>5</ul>

Order does NOT matter

Ordered (numbers)

html
1<ol>2  <li>Fill out form</li>3  <li>Attend orientation</li>4  <li>Pay membership fee</li>5</ol>

Order IS critical

i
Nested lists go INSIDE the li element. You can mix ul inside ol and vice versa.

Nested Lists Explained

Slide 13 of 34 #

A list inside a list

html
1<ul>2  <li>Frontend Skills3    <ul>4      <li>HTML</li>5      <li>CSS</li>6      <li>JavaScript</li>7    </ul>8  </li>9  <li>Backend Skills10    <ul>11      <li>PHP</li>12      <li>MySQL</li>13    </ul>14  </li>15</ul>

The inner <ul> is placed INSIDE the <li>, after the text and before </li>.

Indentation shows nesting visually but does not affect rendering.

You can nest deeper but avoid going beyond 3 levels — it becomes hard to read.

i
In the browser: indented bullet points under each parent item.

Try It Now: Add an Image

Slide 15 of 34 #

Three minutes — add an image to your page

Step 1: Save an image

Download any image and save it as images/club-photo.jpg in your project folder.

Step 2: Add the tag

html
1<img2  src="images/club-photo.jpg"3  alt="Club members at the annual event"4  width="400"5>

What to check

1. The image appears in the browser — no broken icon.

2. If you see a broken icon, right-click → Inspect → check the src path in the Elements panel.

3. The alt text is descriptive — it says what is IN the image, not just "image" or "photo."

i
The most common error: saving the image in the wrong folder. The src path must match where the file actually is.

Alt Text & Accessibility

Slide 18 of 34 #

Writing good alt text

The alt attribute is NOT optional. Screen readers read it aloud. Search engines rely on it.

!
Describe WHAT THE IMAGE SHOWS. Keep under 125 characters. Never start with "Image of".

Which Format Do I Pick?

Slide 20 of 34 #

Quick decision guide

Photograph? → JPG (millions of colors, small file size)

Logo or icon that must stay sharp? → SVG (scales to any size)

Need transparent background? → PNG (supports alpha channel)

Short animation? → GIF (but consider video instead)

Screenshot? → PNG (preserves text clarity)

×
Always resize images BEFORE uploading. A 5 MB camera photo kills page load speed. Keep content photos under 200 KB.
21

Choosing an Image Format

Slide 21 of 34 #

Format Quick Reference

FormatBest forAvoid when
JPGPhotos, banners, images with many colorsYou need transparency or sharp edges
PNGLogos, screenshots, transparency, sharp edgesThe file is a photograph (use JPG instead)
GIFTiny animations, very few colorsThe image has more than 256 colors
SVGIcons, logos that must stay sharp at any sizeThe image is a photograph
!
Size rules: keep each image under ~200 KB. Resize the file BEFORE inserting — do not just set width/height on a 5 MB photo. Always write alt text.
Speaker notes
Use this table when you are about to insert an image and are not sure which format to save it in. Remember: resize the actual file BEFORE inserting — do not rely on width and height attributes alone to shrink a huge photo.

Discussion: Why Does Alt Text Matter?

Slide 24 of 34 #

Think about accessibility

A blind person uses a screen reader to browse the web.

Without alt text, they hear "image" or the filename — completely useless.

With good alt text, they hear a description and understand the content.

i
Accessibility is not optional. It is a core part of professional web development.

Google also reads alt text for image search rankings.

Common Mistakes

Slide 25 of 34 #

Watch out for these mistakes

×
Skipping heading levels (h1 → h3) — breaks document outline for screen readers
×
Missing or useless alt text ("image", "photo") — defeats accessibility purpose
×
Using huge unoptimized images (5 MB straight from camera) — kills page load speed
×
Using br for layout spacing — use CSS margin/padding instead
×
Content outside li in lists — everything must be wrapped in li tags
×
Multiple h1 tags per page — only ONE h1 allowed per page
×
Wrong image format — using GIF for photos or JPG for logos with transparency

Text & Images: Do vs Don't

Slide 29 of 34 #

Do vs Don't

Do

Use exactly one <h1> per page, then h2, h3 in order

Write alt text that describes the image content

Use <strong> and <em> for meaning

Resize images to their display size before uploading

Use <ul> for unordered and <ol> for ranked lists

Don't

Pick a heading level because you like its font size

Write alt="image" or alt="photo.jpg"

Use <br><br> to fake paragraph spacing — that is CSS margin

Serve a 4000px photo scaled down in the browser

Fake a list with hyphens and <br> tags

Debug This

Slide 30 of 34 #

Four problems in eight lines. Spot them.

html
1<h1>Our Club</h1>2<h3>About Us</h3>3<p>We meet weekly.<br><br>Everyone is welcome.</p>4<img src="images/team.jpg">5<ul>6  <p>Monday</p>7  <p>Wednesday</p>8</ul>
Bug 1

<h3> after <h1> skips h2. Screen reader users navigating by heading think a level is missing.

Bug 2

<br><br> fakes spacing. Use two separate <p> elements and set margin in CSS.

Bug 3

The <img> has no alt attribute. A blind user hears only the file name, or nothing at all.

Bug 4

<ul> may only contain <li> children. Replace both <p> elements with <li>.

i
Run this through validator.w3.org — it flags bugs 3 and 4 instantly.

Practice Checkpoints

Slide 31 of 34 #

How to Know Each Task Is Done

Task 1

Exactly one <h1> on the page, and heading levels descend without skipping.

Task 2

Every <img> has alt text you could read aloud and still understand the page.

Task 3

Both list types render correctly: bullets for <ul>, numbers for <ol>.

Task 4

No image file is larger than about 300 KB, and none is wider than 1200px.

i
Fast alt-text test: hide every image with DevTools. If the page still makes sense, your alt text is doing its job.

Deliverable

Acceptance criteria

One <h1>, at least two <h2> sections, no skipped levels.

At least two images, each with descriptive alt text.

One <ul> and one <ol>, used for the right kind of content.

Before you submit

Validate at validator.w3.org — zero errors.

Read your alt text aloud. Does it describe the image?

Check every image loads — no broken-image icons.

!
Missing alt text is the single most common accessibility failure on the web. Do not add yours to the count.
