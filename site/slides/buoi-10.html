Flash Is Dead

Slide 5 of 30 #

The Rise & Fall of Flash

Flash powered early YouTube, games, and ads for two decades.

Killed by security holes, poor mobile performance, inaccessibility, and the rise of open HTML5 standards.

2010

Apple blocks Flash on iOS

2015

YouTube switches to HTML5

2020

Adobe kills Flash Player

2021+

No browser runs Flash

×
Never use Flash for any new project. It is completely dead.

controlsposterpreloadwidth

7

Video Attributes Reference

Slide 7 of 30 #

All <video> Attributes at a Glance

Essential

controls — show play bar (always add this)

width — player width in pixels

poster — thumbnail before play

preload="metadata" — fetch length only

Optional

autoplay — requires muted

muted — start without sound

loop — repeat when finished

playsinline — prevent iOS fullscreen

!
Boolean attributes (controls, muted, loop) need no value. Just write the name: <video controls muted>.

Source & Codec Selection

How the Browser Chooses a Format

i
Always put type= on every source. Without it the browser downloads each file to check — wasting bandwidth on mobile.
9

Media Format Comparison

Slide 9 of 30 #

Which Formats to Use

Video formats

MP4 (H.264) — universal, always first

WebM (VP9) — 30% smaller, second choice

Ogg (Theora) — obsolete, skip it

Compress with HandBrake before uploading.

Audio formats

MP3 — works everywhere, always first

OGG — better quality, not universal

Keep audio under 5 MB. Use Audacity to compress.

i
Rule of thumb: MP4 + WebM for video, MP3 + OGG for audio. Two sources cover every browser.

Worked Example: Video + Audio

Slide 10 of 30 #

Complete video with poster, controls & fallback

html
1<section class="media-section">2  <h3>Watch Our Promo Video</h3>3  <video controls width="640" height="360"4         poster="images/promo-thumb.jpg"5         preload="metadata">6    <source src="video/club-promo.mp4"7            type="video/mp4">8    <source src="video/club-promo.webm"9            type="video/webm">10    <p>Your browser cannot play this video.11       <a href="video/club-promo.mp4">Download</a>12    </p>13  </video>14</section>
i
Browser shows the poster image first. Clicking play loads MP4 (universal). If MP4 fails, it tries WebM. If both fail, the fallback paragraph with download link appears.

Audio & Autoplay Rules

Slide 11 of 30 #

<audio> & Autoplay

Audio basics

Same pattern as video: controls, multiple <source>, fallback text.

MP3 is universal. Ogg as optional secondary.

No width/height/poster — browser renders a fixed widget.

Autoplay rules

!
Browsers block autoplay WITH sound.

Autoplay requires muted.

Pair with loop + playsinline for background video.

Better UX: let users click play.

Worked Example: Audio Section

Slide 12 of 30 #

Audio player with fallback

html
1<div class="audio-player">2  <h3>Club Anthem</h3>3  <audio controls>4    <source src="audio/anthem.mp3"5            type="audio/mpeg">6    <source src="audio/anthem.ogg"7            type="audio/ogg">8    <p>Cannot play? <a href="audio/anthem.mp3">9      Download the MP3</a>.</p>10  </audio>11</div>
i
Audio follows the same pattern as video: controls attribute, multiple source elements ordered by compatibility, and fallback text with a download link. No poster or dimensions needed.

Try It Now: Add a Poster Image

Slide 13 of 30 #

Three minutes — control what shows before play

Type this

html
1<video controls2       poster="images/promo-thumb.jpg"3       preload="metadata"4       width="640">5  <source src="images/promo.mp4" type="video/mp4">6  <source src="images/promo.webm" type="video/webm">7  <p>Your browser cannot play this video.8    <a href="images/promo.mp4">Download it</a>.9  </p>10</video>

What to check

1. Before you press play, the poster image fills the player.

2. Remove poster and reload — you get a black rectangle instead.

3. preload="metadata" loads only duration info, not the whole file.

4. Browsers try each <source> in order and use the first one they support.

i
Without a poster, most browsers show the first frame — often black. A poster makes the page look finished.

YouTube / Vimeo Embeds

Slide 14 of 30 #

Responsive Iframe Embeds

html
1<div class="video-container">2  <iframe3    src="https://www.youtube.com/embed/VIDEO_ID"4    title="Club Event Highlights"5    allowfullscreen>6  </iframe>7</div>

CSS: padding-bottom: 56.25% on container preserves 16:9 ratio.

Always add title for accessibility. Use YouTube/Vimeo for videos over 5 min.

Try It Now: Add a Video Player

Slide 17 of 30 #

Five minutes — embed a video in your page

Type this into media.html

html
1<section>2  <h2>Club Promo Video</h2>3  <video4    width="640"5    controls6    poster="images/video-thumb.jpg"7    preload="metadata"8  >9    <source src="images/club-video.mp4" type="video/mp4">10    <source src="images/club-video.webm" type="video/webm">11    <p>Your browser does not support HTML5 video.12      <a href="images/club-video.mp4">Download the video</a>.13    </p>14  </video>15</section>

What to check

1. The video player appears with a play button and timeline.

2. Click play — the video should load and play.

3. If you see a black box with no controls, check that controls is spelled correctly.

4. The poster image shows before the video plays.

i
If the video does not play, check the file path. Open DevTools → Network tab → look for a 404 on the video file.

Responsive Media CSS

Slide 18 of 30 #

Making Media Work on Every Screen

Video responsiveness

css
1video {2  max-width: 100%;3  height: auto;4}

Prevents video from overflowing its container on phones.

Audio styling

css
1.audio-player {2  background: #f8f9fa;3  padding: 20px;4  border-radius: 8px;5  margin: 20px 0;6}

Gives the audio widget visual breathing room.

i
Always set max-width: 100% on video elements. Fixed pixel widths break on mobile screens narrower than the video.

Multimedia: Do vs Don't

Slide 19 of 30 #

Do vs Don't

Do

Always add the controls attribute

Provide multiple <source> formats (MP4 + WebM)

Add a poster image so the video looks intentional before play

Set max-width: 100% so media never overflows

Include fallback text inside <video> and <audio>

Don't

Use autoplay with sound — browsers block it and users hate it

Forget the type attribute on <source>

Hard-code pixel widths on video (breaks on mobile)

Upload 200MB video files — compress first or use YouTube

Use <embed> or <object> for video (obsolete)

Media Accessibility

Slide 20 of 30 #

Not Everyone Can Hear or See Your Media

Captions

Add <track kind="captions" src="captions.vtt" srclang="en" label="English"> inside <video>.

Transcript

Provide a text transcript below the player. It helps deaf users AND search engines.

Controls

Native controls are keyboard accessible. Custom controls usually are not.

No autoplay

Autoplaying media disorients screen reader users and people with cognitive disabilities.

iframe title

Every <iframe> needs a title attribute describing what it contains.

!
A video without captions excludes deaf users entirely. A transcript is the minimum accessible baseline.

Try It Now: Responsive Video Wrapper

Slide 21 of 30 #

Four minutes — make an embed scale with the page

HTML

html
1<div class="video-wrapper">2  <iframe3    src="https://www.youtube.com/embed/VIDEO_ID"4    title="Club promo video"5    allowfullscreen>6  </iframe>7</div>

CSS

css
1.video-wrapper {2  position: relative;3  padding-bottom: 56.25%; /* 16:9 */4  height: 0;5}6.video-wrapper iframe {7  position: absolute;8  top: 0; left: 0;9  width: 100%; height: 100%;10}

What to check

1. Resize the browser window — the video should shrink and grow with it.

2. The aspect ratio stays 16:9 — no black bars, no squashing.

3. 56.25% = 9 ÷ 16. For 4:3 video use 75%.

4. The wrapper needs height: 0 or padding-bottom will not work.

i
This trick works because percentage padding is calculated from the element's WIDTH, not height.

Common Mistakes

Slide 22 of 30 #

Seven Pitfalls to Avoid

1. Using Flash or <object> for media — use HTML5 instead

2. Forgetting controls — user sees a frozen rectangle with no way to play

3. Only one obscure format (e.g., Ogg only) — always lead with MP4

4. Autoplay with sound — browser blocks it; add muted

5. Huge uncompressed files — compress with HandBrake / Audacity first

6. Missing title on iframes — screen readers need it

7. Missing type on <source> — browser wastes bandwidth guessing formats

!
Fix: always add controls, always lead with MP4/MP3, always include type=, always compress first.

Debug This

Slide 23 of 30 #

This video has three bugs. Find them.

Buggy HTML

html
1<video width="640" autoplay>2  <source src="club-video.mp4">3  <source src="club-video.webm">4  <p>Your browser does not support video.</p>5</video>

Bugs

1. autoplay without muted — browsers block autoplay with sound. Add muted or remove autoplay.

2. No controls attribute — user cannot play, pause, or adjust volume. Add controls.

3. No poster attribute — video shows a black frame before playing. Add poster="images/video-thumb.jpg".

i
Rule: always add controls. autoplay is almost always a bad UX decision — let the user choose to play.
