What Is a Form?

Slide 5 of 31 #

What Is a Form?

A form collects user data and sends it to a server.

The form element wraps all inputs, labels, and buttons.

action = where data goes; method = how (GET vs POST).

!
Always use method="post" for personal data. Use action="#" while learning.

Slide 6 of 31 #

Check Your Understanding

i
Q1: What are the two required attributes on every form element?
i
Q2: If an input has no name attribute, what happens when the user submits the form?
i
Q3: What is the difference between action and method?

Answers: (1) action and method. (2) The browser sends nothing from that field — the data is lost. (3) action = where the data goes (a URL); method = how it gets there (GET appends to URL, POST sends in the request body).

7

GET vs POST

Slide 7 of 31 #

GET vs POST — When to Use Each

method="get"

Data appended to URL as query string

Visible in address bar and browser history

Bookmarkable (search results, filters)

Size limit ~2048 characters

×
Never use for passwords or personal data

method="post"

Data sent in HTTP request body (not visible in URL)

No practical size limit

Used for registration, login, file uploads

Still needs HTTPS for real security

i
Our default for this course: always post

Try It Now: Build a Minimal Form

Slide 8 of 31 #

Five minutes — prove the form works

Type this into a new file called try-form.html

html
1<!DOCTYPE html>2<html lang="en">3<head><title>Try</title></head>4<body>5  <h1>Sign Up</h1>6  <form action="#" method="post">7    <label for="name">Name:</label>8    <input type="text" id="name"9      name="name" required>10    <button type="submit">Send</button>11  </form>12</body>13</html>

Then verify three things

1. Click the word "Name:" — cursor must jump into the box.

2. Submit empty — browser must block you.

3. Type something and submit — page reloads (action="#").

i
If step 1 fails, your for/id pair is wrong. If step 2 fails, missing required.

Client-Side Validation

Input Attributes Deep Dive

Slide 14 of 31 #

Attributes That Control Behavior

placeholder

Hint text inside the field — disappears on focus. Never a substitute for a label.

autofocus

Cursor starts here on page load. Use on the first field only.

autocomplete

Browser suggests past entries. Set to "off" for sensitive fields like passwords.

disabled

Grayed out, not submitted, not focusable. Use for fields locked by logic.

readonly

Visible and submitted, but the user cannot change it.

value

Pre-fills the field. For radio/checkbox, this is what gets submitted.

html
1<input type="text" name="city"2  placeholder="Hanoi"3  autofocus>
html
1<input type="text" name="id"2  value="STU-2026"3  readonly>

Styling Forms with CSS

Slide 15 of 31 #

CSS Form Styling Essentials

css
1.form-group input, .form-group select,2.form-group textarea {3  width: 100%;4  padding: 10px 12px;5  border: 2px solid #ddd;6  border-radius: 6px;7  font-size: 15px;8  transition: border-color 0.3s;9}1011.form-group input:focus {12  border-color: #2874a6;13  box-shadow: 0 0 8px rgba(40,116,166,0.3);14}

width: 100% makes inputs fill their container for clean alignment.

The :focus pseudo-class adds visual feedback when the user clicks or tabs into a field.

transition creates a smooth color change instead of an abrupt flash.

16

CSS Pseudo-Classes for Forms

Slide 16 of 31 #

Style Every State, Not Just the Default

css
1input:focus {2  border-color: #2563eb;3  box-shadow: 0 0 0 3px4    rgba(37,99,235,.25);5}67input:invalid:not(:placeholder-shown) {8  border-color: #dc2626;9}1011input:valid:not(:placeholder-shown) {12  border-color: #16a34a;13}

:focus — field is active (clicked or tabbed). Always style this for keyboard users.

:valid / :invalid — after the browser checks format (email, pattern, required).

:placeholder-shown — user has not typed yet. Combine with :invalid to avoid red on empty fields.

:required / :optional — target fields by whether they must be filled.

!
Never use :invalid alone — empty required fields turn red before the user types anything.
17

Do vs Don't

Slide 17 of 31 #

Do vs Don't

Do

Use type="email" for email fields

Pair every label with for/id

Share one name on radio/checkbox groups

Use fieldset + legend for long forms

Add required on mandatory fields

Style :focus states for keyboard users

Don't

Use type="text" for emails or phones

Rely on placeholder as the only label

Give radio buttons different names

Self-close textarea (<textarea />)

Forget the name attribute on any input

Remove the default outline without replacing it

Worked Example: register.html

Slide 19 of 31 #

Complete Registration Form

html
1<form action="#" method="post">2  <fieldset>3    <legend>Account Details</legend>45    <label for="fullname">Full Name:</label>6    <input type="text" id="fullname"7      name="fullname" required>89    <label for="email">Email:</label>10    <input type="email" id="email"11      name="email" required>1213    <label for="pass">Password:</label>14    <input type="password" id="pass"15      name="password" minlength="8">16  </fieldset>1718  <fieldset>19    <legend>Membership Level</legend>20    <label><input type="radio"21      name="membership" value="basic" checked>22      Basic (free)</label>23    <label><input type="radio"24      name="membership" value="premium">25      Premium (50k/month)</label>26  </fieldset>2728  <fieldset>29    <legend>Interests</legend>30    <label><input type="checkbox"31      name="interests" value="coding">32      Coding workshops</label>33    <label><input type="checkbox"34      name="interests" value="film">35      Film nights</label>36    <label><input type="checkbox"37      name="interests" value="career">38      Career talks</label>39  </fieldset>4041  <label for="referral">How did you hear42    about us?</label>43  <select id="referral" name="referral">44    <option value="">-- choose --</option>45    <option value="friend">A friend</option>46    <option value="facebook">Facebook</option>47    <option value="poster">Campus poster</option>48  </select>4950  <label for="bio">Short bio:</label>51  <textarea id="bio" name="bio" rows="3"52    maxlength="200"></textarea>5354  <button type="submit">Register</button>55</form>

fieldset + legend groups related fields so screen readers announce the group name first.

for/id pairing: every label's for matches its input's id exactly. This makes the whole word clickable.

name attribute: this is the key the server reads. No name = no data sent.

Radio buttons share one name="membership" so only one can be selected. The checked attribute picks the default.

Checkboxes also share name="interests". All ticked values arrive as a list on the server.

select/option creates a dropdown. The empty first option forces a deliberate choice.

textarea uses rows and maxlength. Never self-close it.

i
This entire form works with action="#" for practice. The browser collects and sends all named fields on submit.

Worked Example: Contact Form

Slide 21 of 31 #

Simpler Contact Form (Line-by-Line)

html
1<form action="#" method="post"2  class="contact-form">3  <fieldset>4    <legend>Contact Us</legend>56    <div class="form-group">7      <label for="c-name">Your Name:</label>8      <input type="text" id="c-name"9        name="name" required>10    </div>1112    <div class="form-group">13      <label for="c-email">Your Email:</label>14      <input type="email" id="c-email"15        name="email" required>16    </div>1718    <div class="form-group">19      <label for="subject">Subject:</label>20      <select id="subject" name="subject">21        <option value="">-- Choose --</option>22        <option value="general">General</option>23        <option value="feedback">Feedback</option>24      </select>25    </div>2627    <div class="form-group">28      <label for="msg">Message:</label>29      <textarea id="msg" name="message"30        rows="5" required></textarea>31    </div>3233    <button type="submit" class="btn">34      Send Message</button>35  </fieldset>36</form>

Line 1–2: form with action="#" and method="post". Class allows targeted CSS.

fieldset + legend: Groups all fields under "Contact Us" heading.

div.form-group: Wrapper div for each label+input pair. Makes spacing via margin-bottom easy.

type="email": Browser checks for @ automatically. On mobile, shows the @ keyboard.

Empty first option: Forces the user to deliberately choose a subject. With required, blocks submission if left blank.

textarea rows="5": Shows five visible lines. Content goes between tags.

button.btn: Styled with gradient, hover lift, and touch-friendly padding.

i
Four input types used: text, email, select, textarea. Fewer than register.html but enough for a simple contact page.

Common Mistakes

Slide 23 of 31 #

7 Common Mistakes (and Fixes)

1. Missing name attribute — data will NOT be submitted

2. Mismatched for and id — label does not link to input

3. Using type="text" for email — no validation, wrong mobile keyboard

4. Self-closing textarea — use <textarea></textarea>, not <textarea />

5. Placeholder as only label — screen readers cannot identify the field

6. Radio buttons with different names — multiple can be selected

7. Forgetting required on mandatory fields — empty submissions go through

Forms Accessibility Checklist

Slide 24 of 31 #

Make Every Form Usable by Everyone

Must Have

Every input has a visible label (not just placeholder)

label for matches input id exactly

Error messages are near the field, not only at the top

Form can be completed entirely with keyboard (Tab, Enter)

Focus order follows visual order (left-to-right, top-to-bottom)

Should Have

aria-describedby links help text to the input

aria-required="true" on required fields (redundant with required but helps older screen readers)

role="alert" on error messages so screen readers announce them immediately

Touch targets at least 44 x 44 px on mobile

i
The for/id pair is the single most important accessibility feature in forms. Get that right first.

Try It Now: One Field, Done Properly

Slide 26 of 31 #

Five minutes, at your desk, right now

Do not build a whole form yet. Build one field correctly, and you have the pattern for every field you will ever write.

Type this into register.html

html
1<form action="signup.php" method="post">2  <label for="email">Email address</label>3  <input type="email" id="email" name="email" required>4  <button type="submit">Join</button>5</form>

Then check all four

1. Click the words Email address. The cursor must jump into the box. That proves for matches id.

2. Submit it empty. The browser must stop you. That is required working.

3. Type abc and submit. The browser must complain about the format. That is type="email" working.

4. Open it on your phone. The keyboard must show an @ key.

i
If any of the four fails, the field is wrong. Fix it before adding a second field.

Debug This

Slide 27 of 31 #

Four bugs in eight lines. Find them before you scroll.

This form looks fine and is broken

html
1<form action="signup.php">2  <label>Full name</label>3  <input type="text">45  <label for="email">Email</label>6  <input type="text" id="email" name="email">78  <input type="submit">9</form>

What actually goes wrong

1. The name input has no name. The server receives nothing for it, silently. Nothing on screen tells you.

2. The first label has no for and the input has no id. Clicking the text does nothing; a screen reader announces an unnamed edit box.

3. Email uses type="text". No format check, and the phone keyboard has no @ key.

4. No method, so it defaults to GET. Every answer ends up visible in the address bar.

!
Three of these four produce no error message anywhere. This is why you test by using the form, not by looking at it.

Practice Checkpoints

Slide 28 of 31 #

How to know each task is actually finished

Working alone? These are your marker. If a checkpoint fails, that task is not done yet.

Task 1

View the page in Chrome. The form outline is visible and the submit button is clickable.

Task 2

Click every label text. The cursor lands in the matching box every time, with no exceptions.

Task 3

Only one radio in a group can be selected at a time. If two can, the group shares no common name.

Task 4

Tab through the form. Each focused field changes appearance. If nothing changes, the :focus rule is missing.

Task 5

Submit the form. The browser leaves the page and lands on confirm.html.

i
Right-click a field and choose Inspect. The Elements panel shows the attributes the browser really parsed, which is not always what you think you typed.

Assignment: Club Registration Form

Slide 29 of 31 #

Handed out now, so you can start while I am still in the room

Deliverable

register.html plus its CSS, inside your Student Club site, linked from the main navigation.

It must collect

Full name, email, student ID, which club, preferred meeting day, and a short reason for joining.

Acceptance criteria — marked on exactly this

Every input has a name, and no two share one.

Every input has a label whose for matches that input's id.

Email uses type="email"; student ID uses a numeric type.

The form uses method="post".

At least three fields are required, and submitting empty is refused.

!
