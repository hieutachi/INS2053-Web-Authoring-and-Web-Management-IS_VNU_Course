What Is a Compact Site?

Slide 5 of 30 #

Compact Site = Small, Focused, Efficient

3-10 pages, each with ONE clear purpose.

Simple flat navigation (4-6 items).

Consistent design via shared CSS.

No redundancy — DRY principle.

Like a well-organized brochure: each panel covers one topic, the flow makes sense, the reader finds what they need quickly.

i
"Compact" means efficient, not cramped. Every pixel earns its place.

Content Grouping Strategy

Slide 6 of 30 #

From Brainstorm to Page List

Step 1 — List ALL content ideas:

Club history, team members, events calendar, photos, videos, contact form, meeting times, social media links, sponsors...

Write everything down without organizing yet.

Step 2 — Group related items into pages:

History + mission → About page

Calendar + past events → Events page

Photos + videos → Gallery or Media page

Form + email + times → Contact page

i
Each page should have ONE clear purpose. If a page covers two unrelated topics, split it.

Navigation Consistency

Slide 10 of 30 #

Same Nav on Every Page

Why consistency matters

Users build a mental model of your site structure.

If the nav changes between pages, users get lost.

Screen readers rely on predictable landmarks.

Same labels, same order, same links on every page.

Common mistakes

Different link text on different pages ("About" vs "About Us")

Links in different order on different pages

Missing links on some pages (e.g., Media only on home)

Broken relative paths in subfolders

i
Fix: copy-paste the exact same nav block into every HTML file. Update all at once when adding a new page.

Try It Now: Consistent Navigation

Slide 11 of 30 #

Four minutes — copy this nav into every page

Paste identically into every .html file

html
1<nav aria-label="Main navigation">2  <ul>3    <li><a href="index.html">Home</a></li>4    <li><a href="about.html">About</a></li>5    <li><a href="events.html">Events</a></li>6    <li><a href="contact.html">Contact</a></li>7  </ul>8</nav>

Then on each page, mark the current one

html
1<li><a href="about.html"2       class="active"3       aria-current="page">About</a></li>

What to check

1. Click through all four pages — the nav never moves or changes order.

2. On each page, exactly one link has class="active".

3. Every link works — no 404s, no broken relative paths.

4. aria-current="page" tells screen readers where you are.

!
The only thing that changes between pages is which link has .active. Everything else is byte-identical.

Favicon & Meta Tags

Slide 12 of 30 #

Polish Details That Matter

Favicon

The small icon shown in the browser tab.

html
1<link rel="icon"2      href="favicon.ico"3      type="image/x-icon">

Use a 16x16 or 32x32 .ico or .png file. Place in root folder.

Unique page titles

html
1<!-- Each page needs a unique title -->2<title>About - Student Club</title>3<title>Events - Student Club</title>4<title>Contact - Student Club</title>

The title appears in the browser tab and search results. Make each one descriptive and unique.

i
Add the favicon link to EVERY page's head section. For pages in subfolders, use ../favicon.ico as the path.

7-Line Spec Template (CLO2)

Slide 14 of 30 #

The 7-Line Specification Template

1# Requirements Specification — [Client name]21. Goal           : [one sentence]32. Target audience: [who visits, devices]43. Pages          : [list, each with one purpose]54. Functional req.: [features: form, table, gallery...]65. Non-functional : [mobile, fast, accessible, editable]76. Out of scope   : [what we will NOT build]87. Success metric : [how we measure success]

"Out of scope" prevents scope creep. Each functional requirement maps to a page or feature.

i
This 7-line spec template is taught for CLO2 requirements analysis. Practice it with any project brief you encounter.

Try It Now: Write a 7-Line Spec

Slide 17 of 30 #

Five minutes — plan a new page from scratch

Your teacher says: "Add a Gallery page to the club site."

markdown
11. Goal: Show club photos and event images22. Audience: Club members and visitors33. Pages: gallery.html (new page)44. Layout: Grid of images, 3 columns55. Colors: Match existing site palette66. Content: 6+ photos with captions77. Deadline: Sunday 23:59

What to notice

Goal is one sentence — what does this page DO?

Audience — who will look at it?

Pages — which file(s) do you need to create?

Layout — how will content be arranged?

Colors — does it match the rest of the site?

Content — what goes on the page?

Deadline — when is it due?

i
You do not need to build it now. The spec is a plan. Write it first, then build.

Site Design: Do vs Don't

Slide 18 of 30 #

Do vs Don't

Do

Keep navigation identical on every page

Use the same CSS file across all pages

Name files in lowercase with hyphens (about-us.html)

Write a spec before you write any code

Add a favicon and meta description to every page

Don't

Duplicate CSS rules in every page's <style> block

Use spaces or capitals in filenames (My Page.html)

Change the nav order between pages — users get lost

Build more than 5 pages for a compact site

Skip the README — graders and future you need it

Checklist

☐ Every page reachable from the home page in one click

☐ Every page links back to index.html

☐ Filenames are lowercase, no spaces, end in .html

☐ 3–5 pages total (not 12)

☐ One shared style.css for all pages

i

Common Mistakes

Slide 20 of 30 #

Seven Pitfalls to Avoid

1. Coding without a plan — draw the site map first

2. Too many pages (15+) — consolidate to 5-6 focused pages

3. Inconsistent navigation — same labels, order, links everywhere

4. Orphan pages — if it is not in the nav, delete it or link to it

5. Duplicate content across pages — DRY + cross-link instead

6. No visual hierarchy — wall of same-size text confuses readers

7. Missing favicon and unique titles — looks unfinished and unprofessional

!
Fix: plan first, keep nav identical, eliminate duplicates, apply heading scale, add favicon to every page.

Debug This

Slide 21 of 30 #

This site has three design problems. Find them.

Scenario

A student submitted a 5-page club website. The teacher opened it and found these issues:

• index.html has the title "Page 1"

• The nav on about.html has 7 links, but contact.html has only 3

• The favicon works on index.html but not on any other page

• README.md says "This is my project" and nothing else

Problems

1. "Page 1" is not a meaningful title — every page needs a unique, descriptive title (e.g., "Home — VNU Club").

2. Inconsistent navigation — the nav must be IDENTICAL on every page. Same links, same order.

3. Favicon only on one page — the <link rel="icon"> must be in the <head> of EVERY page.

i
Bonus: README.md with one line is not documentation. Write: what the site is, how to run it, what tools you used.

Whole-Site Accessibility Checklist

Slide 23 of 30 #

Check Every Page Before You Submit

Structure

lang

<html lang="en"> on every page

title

Unique, descriptive <title> per page

h1

Exactly one <h1> per page, no skipped heading levels

landmarks

header, nav, main, footer on every page

Content

alt

Every <img> has alt (empty alt="" if decorative)

labels

Every form input has a matching <label for="...">

links

Link text makes sense alone — no "click here"

contrast

Text is readable against its background

i
Tab through each page using only the keyboard. If you cannot reach a link or button, it is not accessible.

README Documentation

Slide 24 of 30 #

Document Your Project

What is README.md?

A plain-text file that explains your project to anyone who opens it.

Written in Markdown (simple formatting).

GitHub displays it automatically on the repository page.

Required sections:

1# Student Club Website2A website for the Coding Club at VNU-IS.34## Pages5- Home (index.html)6- About (pages/about.html)7- Contact (pages/contact.html)89## Technologies10HTML5, CSS3, Google Fonts1112## How to Run13Open index.html in any browser.1415## Author16Your Name - Student ID
i
The README is part of your homework submission. Include project title, description, page list, technologies, run instructions, and your name.

Site Review Checklist

Slide 26 of 30 #

Before You Submit — Check Everything

Structure & Links

All pages load without errors

Every link works (click them all)

Navigation is identical on every page

No orphan pages exist

Visual Polish

Images display correctly (no broken icons)

Header and footer are consistent

Unique title on each page

Favicon shows in browser tab

!
Open every page in the browser and click every link. Do not assume links work — test them. A broken link loses marks.
