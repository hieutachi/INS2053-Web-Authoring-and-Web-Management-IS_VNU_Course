Table anatomy

Slide 5 of 30 #

Semantic table structure

Order inside <table>: caption → thead → tbody → tfoot.

<td> and <th> MUST be direct children of <tr> — never directly inside <table>.

6

When to Use Tables

Slide 6 of 30 #

Tables Are for Data, Never for Layout

DO use tables for

Class timetables and schedules

Price lists and fee structures

Member rosters and directories

Statistics and comparison charts

Any spreadsheet-like data

DON'T use tables for

Page layout (header, sidebar, content)

Positioning elements on the page

Creating columns for text flow

Adding spacing between elements

Anything CSS Flexbox can handle

!
Table-based layouts confuse screen readers, break on mobile, and are hard to maintain. Use CSS for layout.
7

Core Table Elements

Slide 7 of 30 #

The Four Core Elements

<table>

Container wrapping the entire table

<tr>

One horizontal row of cells

<th>

Header cell — bold, centred by default

<td>

Data cell — normal weight, left-aligned

html
1<table>2  <tr>3    <th>Event</th>   <!-- header cell -->4    <th>Date</th>5  </tr>6  <tr>7    <td>Workshop</td> <!-- data cell -->8    <td>Mar 15</td>9  </tr>10</table>
!
Critical rule: <td> and <th> MUST be inside <tr>. A cell directly inside <table> is invalid HTML.

Worked Example: Event Schedule

Slide 8 of 30 #

Complete styled table with thead, tbody, tfoot

html
1<table class="styled-table">2  <caption>Upcoming Events — March 2024</caption>3  <thead>4    <tr>5      <th>No.</th><th>Event</th>6      <th>Date</th><th>Venue</th>7    </tr>8  </thead>9  <tbody>10    <tr>11      <td>1</td><td>Web Workshop</td>12      <td>Mar 15</td><td>Room 301</td>13    </tr>14    <tr>15      <td>2</td><td>Photo Contest</td>16      <td>Mar 22</td><td>Online</td>17    </tr>18    <tr>19      <td>3</td><td>Music Night</td>20      <td>Mar 29</td><td>Auditorium</td>21    </tr>22  </tbody>23  <tfoot>24    <tr>25      <td colspan="3">Total Events</td>26      <td>3</td>27    </tr>28  </tfoot>29</table>
i
caption gives the table a title + accessible label. thead wraps header row(s). tbody wraps data rows. tfoot uses colspan="3" so "Total Events" spans three columns while "3" sits in the fourth.
9

Semantic Sections Deep Dive

Slide 9 of 30 #

Why caption, thead, tbody, tfoot Matter

Correct order inside <table>:

1. <caption> — first (if present)

2. <thead> — header rows

3. <tbody> — data rows

4. <tfoot> — summary rows

Why these sections matter:

Accessibility: screen readers navigate by section

Styling: apply different CSS to each section

Print: browsers repeat thead on each printed page

Semantics: machines understand table structure

i
You can have multiple <tbody> sections to group related data. Only ONE <thead> and ONE <tfoot> per table.

Five minutes — build a members table

Type this into tables.html

html
1<table>2  <caption>Club Members</caption>3  <thead>4    <tr>5      <th>Name</th>6      <th>Role</th>7      <th>Joined</th>8    </tr>9  </thead>10  <tbody>11    <tr>12      <td>An</td>13      <td>President</td>14      <td>2024</td>15    </tr>16    <tr>17      <td>Minh</td>18      <td>Treasurer</td>19      <td>2025</td>20    </tr>21  </tbody>22</table>

Then check four things

1. The caption appears above the table — that is the table title.

2. Header row is bold and centered — that is th default styling.

3. Right-click and Inspect — you should see thead and tbody in the DOM.

4. Add a third row with your own name. Every row must have exactly 3 cells.

i
If the table looks like a wall of text with no borders, add border-collapse: collapse in CSS.

What to check

2. Click play — the audio should load and play.

3. If you see nothing, check that controls is spelled correctly.

Worked Example: rowspan Table

Slide 13 of 30 #

Membership fees with rowspan

"Student" spans two rows — the next row has only 3 td, not 4.

html
1<table class="styled-table">2  <caption>Membership Fees</caption>3  <thead>4    <tr>5      <th>Category</th><th>Duration</th>6      <th>Price</th><th>Benefits</th>7    </tr>8  </thead>9  <tbody>10    <tr>11      <td rowspan="2">Student</td>12      <td>1 Semester</td>13      <td>50,000 VND</td>14      <td>All events + workshops</td>15    </tr>16    <tr>17      <!-- No td for Category: rowspan fills it -->18      <td>Full Year</td>19      <td>80,000 VND</td>20      <td>All events + T-shirt</td>21    </tr>22    <tr>23      <td>Guest</td><td>Per Event</td>24      <td>Free</td>25      <td>Single event only</td>26    </tr>27  </tbody>28</table>
!
After rowspan="2", DELETE one td from the next row. Leaving it in creates an extra column and breaks the grid.

Worked Example: Leadership Table

Slide 15 of 30 #

Club Leadership with Email Links

Table cells can contain any inline element — including links.

html
1<table class="styled-table">2  <caption>Leadership Team 2024</caption>3  <thead>4    <tr>5      <th>Name</th><th>Position</th>6      <th>Faculty</th><th>Email</th>7    </tr>8  </thead>9  <tbody>10    <tr>11      <td>Nguyen Van A</td>12      <td>President</td>13      <td>Information Technology</td>14      <td><a href="mailto:president@club.edu">15            president@club.edu</a></td>16    </tr>17    <tr>18      <td>Tran Thi B</td>19      <td>Vice President</td>20      <td>Business Administration</td>21      <td><a href="mailto:vp@club.edu">22            vp@club.edu</a></td>23    </tr>24  </tbody>25</table>
i
The mailto: link inside a <td> opens the user's email client. This is valid HTML — cells accept any inline content.

CSS table styling

Slide 16 of 30 #

Professional table CSS

css
1.styled-table {2  width: 100%;3  border-collapse: collapse;   /* single borders! */4  border-radius: 8px;5  overflow: hidden;6}7.styled-table thead { background: linear-gradient(135deg, #1a5276, #2874a6); }8.styled-table th    { color: white; padding: 12px 15px; text-align: left; }9.styled-table td    { padding: 10px 15px; border-bottom: 1px solid #ddd; }10.styled-table tbody tr:nth-child(even) { background-color: #f8f9fa; }11.styled-table tbody tr:hover { background-color: #eaf2f8; }

Table CSS Reference

Slide 17 of 30 #

Essential Table CSS Properties

Structure & Borders

border-collapse: collapse — single borders

width: 100% — full container width

overflow: hidden — clips border-radius

Visual Polish

padding: 10px 15px — cell breathing room

nth-child(even) — zebra stripe rows

tr:hover — interactive highlight

text-align: left — override th centering

i
Always set border-collapse first. Without it, every cell draws its own border creating ugly double lines.

Try It Now: Style Your Table

Slide 18 of 30 #

Add this to style.css

css
1table {2  border-collapse: collapse;3  width: 100%;4}56th, td {7  border: 1px solid #ddd;8  padding: 10px;9  text-align: left;10}1112th { background-color: #333; color: white; }1314tbody tr:nth-child(even) {15  background-color: #f5f5f5;16}

What to check

1. Borders are single lines, not doubled — that is border-collapse working.

2. Header row is dark with white text.

3. Every other data row has a light grey background (zebra striping).

4. Cells have breathing room from the padding.

i
Remove border-collapse: collapse and reload. See the double borders? That is why it must come first.

Responsive tables

Slide 19 of 30 #

Tables on small screens

html
1<div class="table-wrapper">2  <table class="styled-table">...</table>3</div>
css
1.table-wrapper {2  overflow-x: auto;  /* scrollbar only when needed */3  margin: 20px 0;4}

Tables do not shrink gracefully. Wrap them in a scrollable container so content stays readable on phones.

Table Accessibility

Slide 20 of 30 #

Making Tables Accessible

Screen readers & tables

Screen readers read each cell aloud with its header.

<th> tells the reader "this is a column label".

<caption> is announced first as the table title.

Without these, users hear "cell 1, cell 2..." with no context.

The scope attribute

html
1<th scope="col">Name</th>2<th scope="row">Student</th>

scope="col" = this header labels a column

scope="row" = this header labels a row

Use scope when a table has headers on both axes.

i
Accessibility checklist: caption present, th for headers (not styled td), scope where needed, responsive wrapper for mobile.

Tables & Media: Do vs Don't

Slide 21 of 30 #

Do vs Don't

Do

Use <table> only for tabular data, not for layout

Include <thead>, <tbody>, <tfoot> for structure

Add controls attribute to every <video> and <audio>

Provide fallback text for media elements

Use poster attribute on videos for a thumbnail

Don't

Use tables to create page layouts (use flexbox/grid)

Use autoplay on videos (browsers block it)

Forget the type attribute on <source> elements

Use absolute file paths for media files

Embed videos without responsive wrapper (56.25% padding)

Table Accessibility Checklist

Slide 22 of 30 #

Make Your Tables Accessible

caption

Every table needs a <caption> — it is the table's title for screen readers.

scope

Add scope="col" to header cells in the first row, scope="row" for the first column.

thead/tbody

Use <thead> and <tbody> to separate headers from data — screen readers use this.

Simple tables

Avoid complex colspan/rowspan when possible — they confuse screen readers.

!
A table without <caption> and scope attributes is like an image without alt text — inaccessible.
23

Common Mistakes

Slide 23 of 30 #

Seven Pitfalls to Avoid

1. <td> directly inside <table> without a <tr> wrapper

2. Forgetting border-collapse: collapse → ugly double borders

3. Same number of <td> in every row despite rowspan → extra cell breaks grid

4. Headers styled identically to data cells → no visual distinction

5. Using tables for page layout → bad semantics, poor accessibility

6. Missing <caption> → screen readers cannot identify the table purpose

7. Forgetting responsive wrapper → table overflows on mobile

!
Fix: always wrap cells in <tr>, always collapse borders, always add caption, always use .table-wrapper.

Debug This

Slide 24 of 30 #

This table has three bugs. Find them.

Buggy code

html
1<table>2  <tr>3    <th>Name</th>4    <th>Role</th>5  </tr>6  <tr>7    <td>An</td>8    <td>President</td>9    <td>2024</td>10  </tr>11  <tr>12    <td>Minh</td>13    <td>Vice</td>14  </tr>15</table>

Bugs

1. No thead/tbody — header row and data rows are not separated. Screen readers cannot tell them apart.

2. Row 1 has 3 cells but the header only has 2 columns — the table grid is broken.

3. No caption — the table has no title describing what the data is about.

i
Fix: add thead around the header row, tbody around data rows, add a caption, and make every row have the same number of cells.
